# 繁體中文命令理解流程

本文件對應 `xingcheng` 的可執行 Python 邏輯。系統入口以繁體中文／台灣中文為最高優先，保留使用者原句，不先翻譯成英文再判斷意圖。程式碼、模型名稱、API 名稱、路徑、檔名與其他識別字維持原文。

## 入口主流程

**繁體中文命令 → 中文語意理解 → 意圖解析 → 參數抽取 → 任務分類 → 難度判定 → 安全與權限閘門 → 子任務模型分派 → 執行 → 驗證與修正 → 整合 → 實際操作確認 → 繁體中文回覆**

## 中文命令理解層

1. **原始輸入接收**
   - 完整保留原始繁體中文。
   - 支援台灣口語、省略句、常見錯字、中英混合、模型名稱、路徑與檔名。
   - 不建立英文中介命令。

2. **台灣中文語意正規化**
   - 將同義動作映射為一致語意，例如「刪掉、移除、砍掉」對應刪除。
   - 「看一下、查一下、幫我查」對應查詢。
   - 正規化時保護程式碼、路徑、檔名、URL 與模型識別字。

3. **主動詞辨識**
   - 辨識查詢、建立、修改、刪除、搬移、複製、重新命名、分類、分析、比較、執行、停止及監控。

4. **操作對象辨識**
   - 辨識模型、檔案、資料夾、圖片、影片、程式碼、文字、資料庫、服務、程序及設定檔。

5. **參數抽取**
   - 抽取模型名稱、檔名、路徑、數量、日期、大小、版本、量化格式與排序方式。

6. **限制條件辨識**
   - 支援只用本地、不要 API、不要插件、VRAM 上限、只用最新版、繁體中文輸出及不要生成圖片等限制。

7. **上下文補全**
   - 遇到「它、舊的、上一批、照剛才、執行、繼續」等省略內容時，先讀取同一對話的最近上下文。
   - 上下文只補充省略資訊，不覆蓋最新命令或既有限制。

8. **意圖確定**
   - 將動作、對象、參數與限制整理成明確任務。
   - 分析與建議不自動等同於實際搬移、刪除、覆寫或執行。

9. **任務類型分類**
   - 分為一般中文任務、Coding、視覺、檔案管理、推理、RAG／搜尋、自動化 Agent、系統操作及多模型協作。

10. **任務強度判定**
    - 依動作數、對象數、限制數、跨領域程度、上下文歧義、輸入長度及操作風險，判定輕量、普通、中級或困難。

## 模型分派

- 中文命令理解主模型：`qwen3.8:27b-q4_K_M`
- 中文命令理解備援模型：`qwen3.6:35b-a3b-coding`
- 任務拆解與分派：依結構化理解結果選擇模型，不在理解前先固定整項任務的模型。
- 程式、視覺、搜尋、推理及 Agent 子任務分別依能力與難度路由。
- 多模型交叉驗證只在風險或難度需要時啟用。

## 任務強度與平行調度

| 強度 | 主體配置 | 最大平行分支 | 驗證方式 |
| --- | --- | ---: | --- |
| 輕量 | 小模型直接處理 | 1 | 基本結果檢查 |
| 普通 | 中型主模型＋小模型輔助 | 2 | 依風險啟用驗證 |
| 中級 | 1 個大型主模型＋1～2 個專業模型 | 3 | 專業結果比對 |
| 困難 | 多模型協作 | 4 | 強制交叉驗證 |

強度採可核對計分：多動作、多對象、明確限制、跨領域、上下文歧義、長篇多步驟及系統／Agent／多模型操作各增加 1 分；破壞性操作增加 2 分。0～1 分為輕量、2～3 分為普通、4～5 分為中級、6 分以上為困難。輸出長度上限依序為 256、512、768、1024 tokens。

- 互不相依的子任務可以平行執行；存在依賴關係的階段維持順序。
- 平行結果完成後必須收集、去除衝突並由整合模型產生一致結果。
- 破壞性操作不得平行套用；只能在整合、驗證與安全確認後單一路徑執行。
- 只有模型未安裝、推論失敗或輸出驗證失敗時，才允許自動升級模型。
- 成功的分支不因其他分支失敗而升級；只重試或升級失敗分支。
- 機器可讀規則位於 `config/繁體中文自動模式規則.json`。

## 視覺檔案辨識專員

- 固定模型：`minicpm-v4.6:q8_0`（MiniCPM-V 4.6）。
- 主職責：視覺檔案辨識。
- 允許工作：圖片辨識、影片影格辨識、文件影像辨識、分類、標籤及摘要。
- 封閉範圍：只有 `visual` 子任務可以選擇此模型；一般對話、Coding、推理、RAG／搜尋與系統操作不得路由給它。
- 一般檔案管理只有「視覺辨識」子任務使用 MiniCPM-V 4.6；路徑規劃、重新命名、搬移、刪除與覆寫由其他模型及受治理工具處理。
- MiniCPM-V 4.6 未安裝或辨識失敗時停止視覺分支並回報，不把視覺辨識改派給其他模型。
- 視覺輸入接受圖片、影片抽取影格或文件頁面影像；若沒有視覺資料，回覆 `VISUAL_INPUT_REQUIRED`，不猜測檔案內容。

## 破壞性操作安全閘門

1. 命令理解失敗、指涉不明或目標不具體時，先停止破壞性操作。
2. 優先利用最近對話、已確認意圖與可安全讀取的上下文補全。
3. 補全後重新判定動作、操作對象、具體目標及限制。
4. 若仍有歧義，回覆 `SAFE_CONFIRMATION_REQUIRED`，不執行任何操作。
5. 使用者明確補充操作對象、範圍並確認後，才可繼續通過治理與權限檢查。
6. 即使理解完成，刪除、覆寫、格式化、重置及資料庫破壞性操作仍受平台治理、備份與回復規則限制。

## 結構化輸出

中文理解層使用 `star-semantic-plan/v1`，主要欄位包括：

- `raw_input`：未修改的原始命令。
- `normalized_input`：保護識別字後的台灣中文正規化命令。
- `actions`：主動詞與標準動作。
- `operation_objects`：操作對象。
- `parameters`：路徑、檔名、模型、版本、量化、日期、數量等參數。
- `specific_constraints`：本地、API、插件、VRAM、語言與輸出限制。
- `context_completion`：是否需要、是否嘗試及是否成功使用上下文補全。
- `task_classification`：任務類型及能力需求。
- `task_intensity`：輕量、普通、中級或困難及判定原因。
- `safety`：破壞性、歧義、確認需求及是否允許繼續。
